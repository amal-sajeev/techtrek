§ 01

Design System Overview

TechTrek uses a dark-mode-first cyberpunk aesthetic: near-black backgrounds (#010409 through #1c2128), a dominant cyan accent (#00d4ff), an animated starfield canvas, and glowing borders. The system is coherent and well-executed, with consistent CSS variables throughout.

Typography
Font Choices style.css:30–31
⚠ Moderate

The display font is Orbitron — an excellent, on-brand choice that perfectly fits the sci-fi/tech summit tone. The body font, however, is Space Grotesk, which is one of the most over-used fonts in AI-generated UIs and generic SaaS products. On a platform as distinctive as TechTrek, the body font is the character backbone — the current choice mutes the brand's energy.

--font-display: 'Orbitron', monospace; /* ✓ Great pick */ --font-body: 'Space Grotesk', ...; /* ✗ Too generic */
💡 Replace Space Grotesk with something more characterful. Syne (geometric, technical), Barlow (condensed at headings, regular at body), or Rajdhani (Indian-tech aesthetic) would set TechTrek apart. Exo 2 is already in the Google Fonts import — it pairs well with Orbitron and has unused weight variants.
Unused Font Imports
ℹ Info

The <base.html> imports 6 Google Font families (Orbitron, Space Grotesk, Exo 2, JetBrains Mono, Playfair Display, Libre Baskerville, DM Sans, DM Mono) in a single request. Several of these (Playfair Display, Libre Baskerville, DM Sans, DM Mono) appear to be remnants from design exploration and are not referenced in the CSS.

💡 Audit and trim the font import. Remove any family not actively used in CSS. Each extra family adds ~40–80 ms of render-blocking load time.
Color & Theme
Dark/Light Mode Duplicate Markup
✗ Issue

The home page has completely separate HTML blocks wrapped in .dark-only and .light-only CSS classes. This means the hero section renders two full versions of the content simultaneously, hidden by CSS — doubling the DOM size, potentially confusing screen readers, and making maintenance harder.

/* In home.html */ <div class="dark-only">...full hero version 1...</div> <div class="light-only">...full hero version 2...</div>
💡 Use a single HTML block and apply theme-specific styles via CSS only. Use [data-theme="light"] selectors to swap colors and text rather than duplicating markup.
Base Font Size
⚠ Moderate

The body font size is set to font-size: 19px — unusually large for a web app. This makes body copy feel oversized in form inputs, table cells, and dense admin views. Most modern design systems use 15–16px for body text and scale up headings.

💡 Bring base font size down to 15–16px. Use rem units throughout so everything scales proportionally. The current 19px makes the admin data tables feel cramped in comparison.
Motion & Animation

The animated starfield canvas is a strong visual signature for dark mode. Flash messages and modals appear to have minimal transitions. Overall the animation level is appropriately restrained for an event platform.

§ 02

Public-Facing Pages

Home Page /
Featured Event Hero — Excellent
✓ Strong

The featured event hero card with countdown timer (X days Y hours), session count, date chip, and venue chip is well-designed. The overlay layout with a semi-transparent gradient over a full-bleed image creates an atmospheric dark-mode first impression.

Single-Event Mode vs. Multi-Event Mode
⚠ UX Gap

The navbar and footer conditionally hide the Home and Events links when there is only one event ({% if total_events > 1 %}). This is a clever micro-optimization, but it creates an inconsistent navbar depending on the data state. A first-time visitor seeing only a logo and Login/Sign Up might not know what the platform does.

💡 Even in single-event mode, keep "Events" in the navbar (it simply links directly to the one event's detail page). Or add a brief tagline next to the logo like "India's Campus Summit" permanently visible on mobile.
Hero Sub-copy
ℹ Minor

The dark-mode hero reads: "The best campuses don't just teach tech — they live it. TechTrek brings working engineers and founders straight to your campus — live talks, real insights, zero fluff." This is punchy and on-brand. However, there's no secondary CTA (e.g., newsletter signup or "Learn More") visible on the hero when the featured event CTA is absent.

Events Listing /events
Date Bucketing — Great Pattern
✓ Strong

Splitting events into "This Week", "Next Week", and "Later" buckets is a smart date-grouping pattern. It gives users immediate temporal context without needing to read date strings.

Filter Reloads Page — No Live Search
⚠ Moderate

The city filter and sort order trigger a full page reload via form GET submission. This causes a jarring blank-reload UX, especially on slower connections. The search input in the Admin dashboard uses client-side filterEMCards() which is instant — the public events filter should behave the same way.

💡 Add a client-side filter: debounce the search input to filter visible cards in-DOM, and change city/sort to trigger fetch instead of reload. If SSR is required, at least keep scroll position and selected values after the reload.
Event Detail /events/:id
Scroll Progress Bar + Sticky Title — Excellent
✓ Strong

The .ed-progress-bar and the .ed-sticky-title that appears as the user scrolls are excellent UX patterns on long event detail pages. The sticky bar includes the "Book Now" CTA so the conversion point is always visible.

Hero Carousel Sources
ℹ Info

The carousel uses Unsplash photos as fallback images keyed by event.id % 8. This means every event will always show the same Unsplash photo (deterministic hash), which looks intentional but may feel repetitive as the platform grows. The gallery upload system is in place — the fallbacks are just for events without custom images.

💡 Consider adding an admin-side prompt to upload a banner when an event is published, to ensure no events use the generic Unsplash defaults in production.

Registration Friction — 8+ Required Fields
✗ Critical

The registration form requires: Full Name, Username, Email, College, Discipline (select), Specialization (text), Year of Study (select), Password, Confirm Password — 9 required fields plus an optional phone number. For a student trying to quickly book a tech event, this is a significant barrier. Discipline, Specialization, and Year of Study are profile-enrichment fields that don't need to gate the account creation step.

The form also includes a full custom country-code phone picker component, which adds visual complexity for what is an optional field.

💡 Split registration into two steps: (1) Essential: Name, Email, Password — account created, redirect to booking. (2) Optional on first login or via a "Complete Profile" prompt: College, Discipline, Specialization, Year. This aligns with the copy "It only takes 30 seconds" — currently it does not.
Login Page — Clean & Functional
✓ Strong

The login page is well-executed: inline validation, progressive error messages, loading state on the submit button, and a "Forgot your password?" link in a logical position. The optional Google SSO button is shown conditionally based on server config. The "next" redirect parameter properly passes through so post-login redirects work.

Password Strength Indicator
✓ Strong

The password strength bar updates live as the user types, using a 4-point scoring system (length, uppercase, numbers, special chars) with color-coded feedback (red → amber → green → cyan). This is a high-quality UX detail — clear and non-intrusive.

Auth Box Branding
ℹ Minor

The auth box header shows ⚡ TECHTREK as a plain text string. While consistent with the overall branding, there's an opportunity to make the auth pages more atmospheric — a subtle background texture, a thin cyan glow on the card, or the starfield animating behind the auth box rather than a plain page.

💡 The auth page .auth-page wrapper could have a subtle radial glow centered on the box in dark mode. Small but makes the experience feel cohesive with the rest of the site.

Interactive Seat Map — Excellent
✓ Strong

The seat picker is one of the best features of the platform. It has a proper legend (Available, Selected, Taken, VIP, Accessible, Reserved), keyboard navigation support (aria-label on the map container), seat type badges, and live selection state. The pinch-to-zoom / scale wrapper for mobile is a strong addition.

Checkout Timer — Good, but Anxiety-Inducing
⚠ Consider

The countdown timer holding the selected seats adds urgency and prevents indefinite holds. However, the timer begins immediately when the user lands on checkout — if the user is reading the event details or reviewing add-ons, the clock ticking can feel stressful. The current hold timeout is 5 minutes (from hold_timeout_minutes in config).

💡 Consider extending the default timer to 8–10 minutes for Indian students who may be on slower 4G connections. Alternatively, add a "Not ready yet?" escape hatch that explicitly returns seats to the pool without penalizing the user.
Coupon Code UX — Functional
✓ Good

The coupon code input with a dedicated Apply button and a message span for success/error feedback is well-structured. It persists the coupon_code in the form context so page refreshes don't lose the applied code.

Duplicate Seat Listing in Checkout
⚠ Minor UX

The checkout page shows selected seats twice: once in a .checkout-seat-list chip row at the top, and again as individual line items in the .checkout-summary section. For a user with 2–3 seats this feels redundant. The chip row adds visual confirmation but the summary section already does that job with prices.

💡 Keep the chip row for quick visual confirmation, but make the summary section the single source of truth for line items. Remove the redundant seat chips or collapse them into the summary.
Confirmation Page — Solid
✓ Strong

The confirmation page includes individual QR codes per ticket, a group QR for multi-seat bookings, shareable ticket links, cancellation policy notice, and a "View Invoices" link. This is thorough and well-organized.

One note: the confirmation icon is ✓ (Unicode checkmark) which is small and low-impact. Given this is the most important moment in the user's journey, a more celebratory icon or brief animation would create a better emotional peak.

Hardcoded Cancellation Fee Message
⚠ Minor

The confirmation page displays: "Cancellation policy: ₹100 fee per ticket, remainder refunded." This fee amount is hardcoded in the Jinja template rather than pulled from a configurable setting, meaning it would need a template edit to change.

💡 Add a cancellation_fee field to the event model or pull it from SiteSettings so different events can have different policies, and admin can update it without a code deploy.
My Bookings Page — Clean
✓ Good

The bookings list uses status badges (Confirmed, Cancelled, Partial), date/venue detail rows with emoji icons, total paid display, and seat chip previews. It's readable and scannable. Cancelled bookings are visually distinguished by a .booking-cancelled class with muted styling.

§ 05

Admin Portal

Sidebar Navigation — Structural Issue
✗ Issue

The sidebar navigation groups items into three sections:

  • Events & Content: Events, Sessions, Bookings, Waitlist
  • People & Places: Cities, Colleges, Speakers, Users
  • Communications: Newsletter, Seat Types, Feedback, FB Templates, Cert Templates, (System)

Seat Types is misplaced in Communications. Seat Types are a venue configuration that belongs under Events & Content. Certificate Templates are a recognition/documentation tool, not a communication. Feedback Templates are likewise not communications.

💡 Reorganize the sidebar:
• Events & Content: Events, Sessions, Bookings, Waitlist, Seat Types
• People & Places: Cities, Colleges, Speakers, Users
• Communications: Newsletter, Feedback, Feedback Templates
• Recognition: Certificate Templates
• System: Settings, Activity Log, Metrics
Dashboard Stat Cards — Functional but Flat
⚠ Moderate

The dashboard shows 6 stat cards (Total Users, Confirmed Bookings, Total Revenue, Upcoming Events, Total Check-ins, Refunded). The cards are clear but there's no trend indicator, no comparison to previous period, and no sparklines. For an admin checking on event health, "are things going up or down?" is the key question the current stats don't answer.

💡 Even simple indicators help: a ↑/↓ icon with "vs last week" for revenue and bookings. The metrics page likely has this data — consider surfacing the most recent delta on the dashboard cards.
Event Management Hub — Well Designed
✓ Strong

The per-event management hub (/admin/event-management/:id) with tabs for Overview, Bookings, Check-in, Polls, Alerts, Feedback, Recordings, Report, and Waitlist is a comprehensive and well-organized structure. Having all event-specific operations in one place is the right architecture decision.

Event Cards — Missing Quick Actions
⚠ Minor

The active events grid cards show booking counts and check-in numbers but don't surface any quick actions. Admins frequently need to: open the check-in scanner, send an alert, or view the booking list for a specific event. Currently they must click into the event hub first.

💡 Add 2–3 inline quick-action buttons on the event card hover state: "Check-in", "Alerts", "Bookings". This would save admins 1–2 clicks for the most common operations during a live event.
Admin Sidebar Uses Emojis as Icons
ℹ Minor

The admin sidebar uses HTML entity emojis (📈, 🏆, etc.) as nav icons. These render inconsistently across OSes — emoji rendering on Windows is noticeably different from macOS or Android. The rest of the app uses inline SVGs which look sharp at all sizes.

💡 Replace sidebar emoji icons with consistent SVG icons from Heroicons, Lucide, or Tabler. This also makes it easier to apply consistent sizing and CSS coloring to match the active/hover states.
§ 06

Speaker Portal

Extremely Thin Dashboard
✗ Issue

The speaker dashboard has 3 stat cards (Total, Upcoming, Completed sessions) and just two navigation cards: "My Sessions" and "My Schedule". There's no at-a-glance view of the next upcoming session, no quick access to polls for a live session, and no notification of feedback from past sessions.

For a speaker arriving at the dashboard on the day of their event, the current view gives them no actionable information without navigating away.

💡 Add a "Next Up" section below the stats: show the next upcoming session (title, event name, time, location) with direct links to view polls and session agenda. Speakers don't need the full sessions list — they need the relevant one highlighted immediately.
No Session-Day Tools on Dashboard
⚠ Moderate

During a live session, a speaker needs to: launch a poll, view live poll results, and see how many people are in the audience. None of these are accessible from the dashboard — the speaker must navigate to My Sessions → specific session → Polls.

💡 Add a "Live" indicator and a "Launch Poll" quick-button for currently running sessions. Consider a dedicated "Live Session" mode view that shows polls, attendee count, and a timer.
Nav Cards Pattern — Borrowed from Supervisor
ℹ Info

The speaker dashboard uses the exact same .speaker-nav-card component as the supervisor portal. This is consistent but also means the two portals feel visually identical. Since speakers and supervisors have quite different roles, distinct visual identities would help users orient themselves.

§ 07

Supervisor Portal

Good College-Scoped View
✓ Strong

The supervisor portal correctly scopes all data to their assigned college. The "Upcoming Events" table on the dashboard provides a clear college-specific picture. The three nav cards (Check-in, Bookings, Schedule) cover the primary supervisor workflows.

No Quick-Scan Entry Point from Dashboard
⚠ Moderate

The check-in scanner is 2 clicks away from landing on the supervisor dashboard. During a live event, supervisors at the gate need instant access to the scanner. Having the QR scanner card prominent on the dashboard is good, but there's no event-specific pre-selection: the supervisor must then choose which event to scan for on the check-in page.

💡 If there's only one currently active event at the college, the Check-in card should link directly to that event's check-in view — skip the event selection step. If multiple events, show event chips directly on the dashboard card.
Upcoming Events Table — Missing Status Column
ℹ Minor

The upcoming events table has columns: Event, Date, Auditorium, Bookings, Checked In. It's missing a Status column (Published / Draft / Live) which is important for supervisors to know if an event is publicly visible and whether check-in should be active.

💡 Add a Status badge column. When an event is "Live Today", highlight the row with a subtle accent border to draw immediate attention.
§ 08

Accessibility & Mobile

ARIA Labels Present — Good Foundation
✓ Good

The seat map has aria-label and role="group" attributes. The poll popup modal uses role="dialog" aria-modal="true" aria-labelledby. Flash messages use role="alert". The alert popup uses aria-labelledby for the title. This is a solid accessibility foundation.

Mobile Navigation — Hamburger Drawer
✓ Good

The mobile nav drawer includes all navigation links, theme toggle, and user info (signed-in state). The overlay dismisses on tap. This is a well-structured mobile navigation pattern.

Starfield Canvas on Low-End Devices
⚠ Consider

The animated starfield is rendered on a <canvas> element in dark mode. On low-spec Android devices common in India (budget Redmi, Realme, etc.), canvas animations can consume battery and throttle page interactivity.

💡 Check prefers-reduced-motion and pause canvas animation when set. Also consider detecting low-memory devices via navigator.deviceMemory < 2 and disabling the animation. The CSS particle/grain alternative would be zero-CPU.
Contrast in Dark Mode — Verify Muted Text
⚠ Check

--text-muted: #a8b4c0 on the dark background #0d1117 gives approximately 4.8:1 contrast — just above the WCAG AA minimum of 4.5:1. This is technically compliant but very marginal. The --border: rgba(0,212,255,0.1) used for dividers would fail contrast checks for any text placed over it.

💡 Increase --text-muted to #b8c4d0 or brighter to give more headroom above the AA threshold. Run a contrast audit pass for all text-on-background combinations.
PWA Setup — Complete
✓ Strong

Service worker, manifest.json, offline page, and install prompt button are all present. The theme color is set to the brand cyan. Apple Web App meta tags are included. This is a well-deployed PWA setup for an event platform where users want offline ticket access.

§ 10

Priority Roadmap

Ordered by user-impact / effort ratio. Items at the top should be addressed first:

  • 1
    Reduce registration to 3 essential fields. The single biggest barrier to conversion is the 9-field sign-up form. Move college/discipline/domain/year to a deferred "Complete Profile" step. This change alone could significantly improve sign-up-to-booking conversion rate.
  • 2
    Replace Space Grotesk body font. Swap to Exo 2 (already imported) or Syne for a more distinctive, on-brand body typeface. Takes 5 minutes but immediately elevates perceived design quality.
  • 3
    Events listing — client-side filtering. Eliminate the jarring full-page reload when searching/filtering events. Debounce the search input and use JS to filter visible cards instead. The admin dashboard already does this with filterEMCards() — extract and reuse.
  • 4
    Refactor dark/light mode from duplicate markup to CSS-only. The .dark-only / .light-only pattern doubles the DOM. Migrate to [data-theme="light"] CSS overrides on a single HTML structure.
  • 5
    Speaker dashboard — add "Next Up" session and live session tools. Speakers need instant access to their current/next session and its polls without digging through the sessions list.
  • 6
    Admin sidebar navigation — fix groupings. Move Seat Types to Events & Content, create separate Recognition group for Certificate Templates, and replace emoji icons with SVGs.
  • 7
    Supervisor quick check-in. When there's a single active event at the college, the Check-in card should link directly to that event's scanner — not to a selection page.
  • 8
    Add trend indicators to admin dashboard stat cards. Even simple ↑/↓ comparison values vs. last week would make the dashboard actionable rather than just informational.
  • 9
    Audit muted text contrast. Increase --text-muted brightness slightly and run a full WCAG contrast pass on muted/secondary text in both dark and light themes.
  • 10
    Canvas starfield — respect prefers-reduced-motion. Pause animation for users who have requested reduced motion. This is both an accessibility and a performance win.
