🔴 Critical — Blocking / Revenue-Impacting

3 findings
C-1   Admin Dashboard /admin/ returns 500 and crashes the server
Flow 12 Admin

Navigating to /admin/ consistently returns 500 Internal Server Error. The single-worker uvicorn process hangs indefinitely, eventually becoming unresponsive and requiring a manual restart. All other admin sub-routes (/admin/events, /admin/bookings, etc.) work correctly.

Root cause: the dashboard handler likely performs an N+1 query — iterating over all active events and lazily loading ev.event_sessions for each without a JOIN or selectinload. Under SQLite, this serialises into a blocking loop that starves the single-threaded event loop.

Recommended Fix
In the /admin/ route handler, replace lazy-loaded session counts with a single aggregated query: SELECT event_id, COUNT(*) FROM sessions GROUP BY event_id. Alternatively add options(selectinload(Event.event_sessions)) to the main events query so SQLAlchemy batches it into one additional SQL call instead of N calls. Also add a 5-second DB query timeout so a slow dashboard never kills the entire process.
C-2   All individual ticket QR code images are broken on confirmation and booking detail
Flow 9 Flow 11 Booking

On /booking/confirm/{ref} and /booking/my/{ref}, the per-ticket QR code <img> elements fail to load — only the alt-text is displayed. This means attendees cannot retrieve their QR codes for event check-in after booking, which is the primary way entry is validated on the day.

The booking summary QR (the single-booking level QR) appears to work; only the per-ticket / per-seat QR images in the expanded ticket rows are broken.

Recommended Fix
Check the endpoint that generates per-ticket QR images (likely GET /booking/ticket/{ticket_id}/qr or similar). Verify it: (1) exists and is mounted, (2) returns a valid image content-type, (3) does not require a session cookie that isn't forwarded when the <img src> loads cross-context. Add an onerror handler on the img to show a retry button, and pre-generate QR PNGs at booking time rather than on-demand to avoid cold-path failures.
C-3   /bookings returns 404 — natural navigation URL is dead
Flow 10 Navigation

The logical URL a user would type or share — /bookings — returns a 404. The actual route is /booking/my (singular, with a sub-path). Any external link, email deep-link, or bookmark pointing to /bookings silently breaks. The nav bar also shows "BOOKINGS" as a link, but its destination uses the non-obvious path.

Recommended Fix
Add a redirect: GET /bookings → 301 /booking/my. Also consider renaming the route to /bookings entirely and updating all internal hrefs and the email confirmation links, since the plural form is the convention users expect.

🟠 High — Significant UX Impact

8 findings
H-1   Razorpay modal blocks test flow — mobile number dialog cannot be dismissed
Flow 8 Payment

After the Razorpay modal opens, a "Enter your mobile number" overlay appears inside the cross-origin iframe. There is no skip/close affordance and the back-button behaviour navigates away from the page instead of dismissing the dialog. In production (non-test mode) this step is optional, but in Razorpay's test environment it is gating.

This means QA and any user in an unsupported network environment cannot complete the payment flow without a mobile number, even for a ₹0 test transaction.

Recommended Fix
Switch to Razorpay's Test Mode with pre-filled options: pass prefill: { contact: "9999999999", email: "test@test.com" } in the Razorpay options object so the modal skips the data-collection step in test environments. In production this pre-fill is respected as a default, not a lock.
H-2   Username field is cleared after a failed login attempt
Flow 3 Auth

When login fails (wrong password), the form re-renders with both the username and password fields empty. Standard UX practice is to retain the username so the user only has to re-enter the password. Having to retype the username causes frustration, especially on mobile, and can lead to copy-paste errors.

Recommended Fix
In the login POST handler, re-render the template with username=form_data.username (but not the password). This is a single line change in the Jinja2 template context: {"username": attempted_username}, then set value="{{ username | default('') }}" on the input.
H-3   Checkout card is narrow on 1920px — large whitespace bands on both sides
Flow 7 Checkout

The checkout form is constrained to ~700px wide and centred, leaving over 600px of empty dark void on each side at 1920px. At 125% zoom this is even more pronounced. For a premium event platform the checkout page should feel spacious and deliberate, not like a narrow mobile-first form stranded on a large screen.

Recommended Fix
Use a two-column layout on wide viewports: order summary / seat details on the left, payment form on the right (similar to Stripe Checkout). Apply max-width: 960px with a two-column grid at min-width: 900px. This also gives space to show add-on upsells more prominently.
H-4   Add-on checkbox appears before T&C checkbox in DOM — wrong logical order
Flow 7 Checkout

In the checkout form DOM, the add-on selection checkbox is rendered before the Terms & Conditions acceptance checkbox. Logically and legally, T&C acceptance should be the last gate before payment confirmation, not buried between product options. This may also have legal implications if a user can argue they were misled about what they agreed to.

Recommended Fix
Reorder the form sections: 1) Seat summary, 2) Add-ons / upsells, 3) Terms & Conditions acceptance, 4) Pay button. The T&C checkbox should be the last interactive element before the payment CTA.
H-5   Ticket UUID not truncated in booking confirmation table and admin bookings
Flow 9 Flow 13 Flow 15b Tables

In the booking confirmation page, the Event Management Hub report tab, and the Admin Bookings list, the TICKET column displays the full UUID string (e.g. a3f4c8d2-91b0-4e7a-bc12-…). This causes the column to wrap across two lines, breaking the table's visual rhythm and wasting significant horizontal space.

Recommended Fix
Truncate ticket UUIDs to first 8 characters with a tooltip showing the full value on hover: <span title="{{ ticket.id }}">{{ ticket.id[:8] | upper }}</span>. The booking REF (10-char alphanumeric) is already displayed correctly as a truncated identifier — apply the same pattern to ticket IDs.
H-6   Currency symbol "Rs." used instead of "₹" in event report tab
Flow 13 Admin / Content

The Revenue section of the Event Management Hub report tab displays amounts as Rs. 500 instead of ₹500. The rupee sign ₹ (Unicode U+20B9) is the official ISO 4217 symbol adopted in 2010 and is expected in all modern Indian fintech and event products. Using "Rs." appears dated and inconsistent with the rest of the UI.

Recommended Fix
Create a Jinja2 filter or template macro: {{ amount | inr }} that outputs ₹{{ "{:,.0f}".format(amount) }}. Replace all occurrences of Rs. in templates. Ensure the font (Orbitron/Space Grotesk) supports U+20B9 — if not, use a fallback: font-family: 'Space Grotesk', system-ui which includes it.
H-7   Admin Users page has no "Remove Admin / Make User" demote option for regular users
Flow 16a Admin

For users who are already at the USER role level, there are only MAKE ADMIN, MAKE SUPERVISOR, and DELETE options — no REMOVE SUPERVISOR for regular users. While an admin can have REMOVE ADMIN and REMOVE SUPERVISOR applied to them, there is no way to demote a plain USER back from a promoted state without DELETE+recreate. The UI also has no role filter on the search, making it hard to find all supervisors quickly.

Recommended Fix
Show contextual action buttons based on current role: if role == SUPERVISOR show "REMOVE SUPERVISOR" instead of "MAKE SUPERVISOR". Add a role filter dropdown (All / User / Supervisor / Admin / Speaker) to the search area, using the same TomSelect component used elsewhere in the admin.
H-8   Speaker sessions list layout broken at 1920px — stats float right, heading left
Flow 17b Speaker

On /speaker/sessions, the three stat cards (Total / Upcoming / Completed) float into the upper-right of the content area while the "My Sessions" heading sits at the mid-left, creating a visually disconnected and unbalanced layout. At smaller viewports this collapses naturally, but at 1920px it looks unintentionally broken.

Recommended Fix
Replace the float-based layout with a flex or grid row: put the heading and the three stat mini-cards in a display: flex; justify-content: space-between; align-items: center row at the top of the page. The stat cards should be inline with the heading, not floating independently.

🟡 Medium — Noticeable but Non-Blocking

9 findings
M-1   Password strength indicator renders as a near-invisible 5px underline
Flow 2 Registration

The password strength bar below the password input is only ~5px tall — virtually invisible to most users. It provides no colour-coded segments (weak/fair/strong) and no textual label. Users have no clear signal about password quality until a validation error fires on submit.

Recommended Fix
Increase the bar to at least 6px height with 4 coloured segments (red → orange → yellow → green). Add a text label beneath: "Weak / Fair / Strong / Very Strong". Consider using the zxcvbn library already common in FastAPI stacks for realistic strength scoring.
M-2   Error toast appears in top-right corner — far from the form it describes
Flow 3 Auth / UX

Login and registration error messages appear as toasts in the top-right corner of the viewport — over 1000px away from the form fields at 1920px. Users may miss the error entirely and repeatedly submit the form thinking nothing happened. Form-level inline validation errors are the standard pattern for authentication failures.

Recommended Fix
For auth errors specifically, render an inline error banner directly above the submit button (or below the last field), in addition to (or instead of) the toast. Reserve toasts for non-blocking notifications (email sent, booking saved). Use a red-bordered <div role="alert"> block inline in the form HTML.
M-3   Seat selection coordinate clicks unreliable under CSS zoom
Flow 6 Seat Map

When the page is zoomed to 125% using document.documentElement.style.zoom, seat SVG/element coordinate hit-targets become misaligned with the visual position. Real users at OS-level scaling (Windows Display Settings → 125%) will experience the same offset, making seat selection require multiple attempts to hit the right seat.

Recommended Fix
Replace coordinate-based click handling with element-based event listeners (element.addEventListener('click', …)) on the seat elements. Avoid reading getBoundingClientRect() without accounting for window.devicePixelRatio and CSS zoom. Using pointer events on the seat elements themselves is immune to zoom offsets.
M-4   Footer shows "LOGIN" link even when the user is authenticated
Flow 17b Global / Speaker

The page footer on the speaker session edit form includes a "LOGIN" link even when the user is logged in as a speaker. This is confusing — a logged-in user should not be prompted to log in again. The footer template is likely not receiving the auth context that the header uses.

Recommended Fix
In the shared footer template, check {% if request.session.get('user_id') %} and conditionally render a "My Account" or username link instead of LOGIN. The template_ctx() helper already injects current_user — ensure footer.html references it.
M-5   "Agenda Items" heading uses Title Case while surrounding labels are ALL CAPS
Flow 17b Speaker / Design Consistency

In the speaker edit session form, the "Agenda Items" section heading uses standard Title Case, while every other form label (TITLE, SPEAKER, MIN, BANNER IMAGE, GALLERY IMAGES, PARENT EVENT) uses ALL CAPS monospace styling. This one inconsistency breaks the visual rhythm of the form.

Recommended Fix
Apply the same label class to "Agenda Items": <h3 class="form-section-label">AGENDA ITEMS</h3>. Alternatively, adopt Title Case consistently across all form section headings — just pick one and apply it everywhere.
M-6   Supervisor check-in form is narrow and left-aligned at 1920px
Flow 18c Supervisor

The supervisor check-in UI (/supervisor/checkin) presents a ~450px wide form that sits in the left portion of the content area, leaving the right half of the screen completely empty. For a task that supervisors perform repeatedly in high-pressure situations (event day), the UI should be large and prominent — particularly the QR scanner button and manual entry field.

Recommended Fix
Centre the check-in card both horizontally and vertically within the content area. Increase the QR scanner box to at least 300×300px. On large screens, show a live recent-check-ins feed on the right side of the layout (last 10 scanned attendees with name, time, and status).
M-7   Supervisor bookings status filter uses unstyled plain select
Flow 18b Supervisor

The STATUS filter on /supervisor/bookings appears as a bare, un-styled browser <select> element ("All") next to the FILTER button — inconsistent with the TomSelect-styled dropdowns used throughout the admin and the event-selection dropdown on the same page's sibling view.

Recommended Fix
Apply the same TomSelect initialisation to this <select>: new TomSelect('#status-filter', {create: false}). Alternatively, replace with a set of filter pills (All · Paid · Cancelled · Refunded) which are visually faster to tap on mobile/tablet.
M-8   My Bookings list has inconsistent emoji icons across booking states
Flow 10 Booking

The My Bookings list at /booking/my uses emoji icons (🎫, ✅, ❌) to represent booking states, but the selection appears ad-hoc and the sizes render inconsistently across platforms (they are especially small or invisible on some Linux emoji fonts). Icons should use SVG or a consistent icon font rather than Unicode emoji for guaranteed rendering.

Recommended Fix
Replace inline emoji with inline SVG icons or a consistent icon set (e.g. Lucide or Heroicons which are already used elsewhere in the UI). This guarantees size, colour, and rendering consistency across all OS/browser combinations.
M-9   Admin Speakers "All Roles" filter takes up full content width unnecessarily
Flow 16c Admin

The role filter dropdown on /admin/speakers stretches to the full width of the content area (over 1200px) before the search field appears below it. A TomSelect single-select for 3–4 role options should be at most 200–250px wide. The over-stretched field looks like a layout defect.

Recommended Fix
Constrain the filter to max-width: 240px and place it inline with the search bar in a flex row (filter left, search right), matching the pattern used on /admin/bookings and /admin/sessions.

🟢 Low — Polish & Nice-to-Have

5 findings
L-1   Admin and supervisor list pages have no server-side pagination
Flow 15–16 Admin / Performance

Pages such as /admin/users, /admin/bookings, and /supervisor/bookings currently load all rows into the page with no pagination. With a small seed dataset this is fine, but at production scale (hundreds of bookings per event) the initial page load will become slow and the table will overflow the viewport.

Recommended Fix
Add ?page=1&per_page=50 query-param pagination. Show a simple "Showing 1–50 of 342" counter and Previous / Next links. The existing search & filter already sends GET requests, so pagination can be appended to the same form action.
L-2   Speaker schedule calendar starts on Monday (European) — Indian convention is Sunday
Flow 17c Speaker / Localisation

The calendar on /speaker/schedule renders MON through SUN (ISO week order, European convention). Indian calendars and most Indian apps follow SUN–SAT order. This is a minor localisation mismatch that may slightly confuse speakers when quickly finding a date by week position.

Recommended Fix
Add a week_start config variable (default: 0 = Sunday) and shift the header row and day-of-week offset logic accordingly. This is typically a 1-line change in the calendar rendering JS/template.
L-3   Seat Types DELETE button has no in-UI confirmation for types that are in active use
Flow 16d Admin

The DELETE button on /admin/seat-types shows for all seat types including Balcony and Premium which are actively assigned to seats in published events. Deleting a seat type that is in use would either fail with a DB constraint error (confusing) or cascade-delete seats (catastrophic). There is no guard or warning shown in the UI.

Recommended Fix
Before showing the DELETE button, check if the seat type is referenced by any seats (SELECT COUNT(*) FROM seats WHERE seat_type_id = ?). If yes, replace DELETE with a greyed "IN USE" badge. If no seats reference it, show the DELETE button with a JS confirm dialog.
L-4   Speaker dashboard "UPCOMING" stat uses Orbitron slashed-zero glyph (Ø-like)
Flow 17a Speaker / Typography

The Orbitron font renders the numeral "0" with a diagonal slash, making it visually indistinguishable from the Scandinavian letter Ø at a glance. For the "0 UPCOMING" stat card, non-technical speakers may briefly misread this as a letter. Other numeric displays in the app (booking refs, prices) don't use Orbitron and are unaffected.

Recommended Fix
Use font-variant-numeric: slashed-zero CSS property if the font supports it, or switch stat numbers on the speaker dashboard to Space Grotesk (which has a standard zero). Alternatively, add "0" to a font-feature-settings: "zero" 0 override to disable the slashed zero.
L-5   Supervisor dashboard heading says "Dashboard" — not specific enough for multi-role users
Flow 18a Supervisor

The h1 on the supervisor dashboard simply reads "Dashboard" — the same generic heading used on several other pages. A user who is both a supervisor and (say) a speaker would have no visual cue about which context they are in. The college name is shown in the top-right corner as secondary text, but the main heading should anchor the page clearly.

Recommended Fix
Change the heading to "Supervisor Dashboard" (matching the page <title> which already reads "Supervisor Dashboard — TechTrek"). Optionally add the college name as a styled subtitle beneath: <p class="subtitle">KSR College of Engineering</p>.
